# `include/vm.h`, `src/vm.c`

*Current as of commit `<hash>`, <date>.*

## §1 — Purpose

The VM executes a `Chunk`. It is a 64-bit stack machine with
three logical stacks (data, call, scope), two memory tiers (the
lexical arena and the RC heap), and a const arena for materialized
string literals.

**What it solves.** Decoding and executing bytecode, marshalling
FFI calls, rendering values for print, managing the arena and RC
heap, and reporting runtime errors with a pc and function index.

**What it does not solve.** It does not validate bytecode
(`validate_bytecode` in `disasm.c` does that). It does not
compile. It does not know what a "function" or "scope" is; both
are conventions the compiler and VM share.

**Conceptual model.** See `arch/runtime.md` for the register set,
the calling convention, the memory model, and worked traces.
This document covers the specific code in `vm.c`: the dispatch
loop, the helper functions, the natives, and the FFI path.

## §2 — Public interface

```c
typedef struct {
    U64*                bytecode;
    size_t              bytecode_len;
    const uint32_t*     lines;
    const uint32_t*     cols;
    const ConstantPool* pool;
    const FuncTable*    funcs;
    const TypeTable*    types;
    const FFITable*     ffi;
    const char**        prog_argv;
    int                 prog_argc;
} VMConfig;

void vm_init(VM* vm, const VMConfig* cfg);
void vm_free(VM* vm);
int  vm_run(VM* vm);
I64  vm_top(VM* vm);
void vm_register_native(VM* vm, int slot, NativeFn fn);
```

**`VMConfig`.** The chunk's parts, borrowed. All pointers must
outlive the VM. `prog_argv`/`prog_argc` carry the program's
command-line arguments.

**`vm_init`.** Zeroes the VM, allocates the lexical arena,
registers all natives, and (if `cfg` is non-NULL) wires the
chunk's parts and materializes the constant pool's strings into
the const arena.

**`vm_free`.** Releases the arena, the const arena, the
`const_ptrs` array, and any grown sink buffers. Does not free any
RC blocks; the RC heap is expected to be empty at exit.

**`vm_run`.** The dispatch loop. Returns 0 on `OP_HALT`, 1 on
any runtime error. On error, `vm->error` (a 256-byte message
buffer), `vm->error_pc`, and `vm->error_func_idx` are set for
the driver's error renderer.

**`vm_top`.** Reads `data_stack[sp-1]`, or 0 if the stack is
empty. Used by the driver to print the return value.

**`vm_register_native`.** Fills a slot in `vm->natives[]`. Slots
outside `[0, MAX_NATIVES)` are silently ignored.

## §3 — The `VM` struct

Grouped by concern.

**Program (borrowed from the `Chunk`).**

```c
U64*                bytecode;
size_t              bytecode_len;
const uint32_t*     lines;
const uint32_t*     cols;
const ConstantPool* pool;
const FuncTable*    funcs;
const TypeTable*    types;
```

**FFI.**

```c
const FFITable* ffi;
char            ffi_error[256];
int             ffi_errno;
bool            native_failed;
```

`ffi_error` is the last dlerror/GetLastError message;
`ffi_errno` is the captured `errno` after the last call.
`native_failed` is set by `NATIVE_ERR` and consumed by the
`OP_CCALL` case.

**Execution state.**

```c
U64 pc;
U64 current_pc;
U64 error_pc;
int error_func_idx;
char error[256];
```

`pc` is the read cursor. `current_pc` is set to `pc` at the top
of each iteration, before operand reads, so a runtime error
reports the *start* of the failing instruction. `error_pc` is
`current_pc` at the moment of failure.

**Data stack.**

```c
U64 data_stack[DATA_STACK_MAX];   // 4096
U32 sp;
U32 fp;
```

**Call and scope stacks.**

```c
CallFrame call_stack[CALL_STACK_MAX];   // 256
U32 call_depth;
ScopeFrame scope_stack[SCOPE_STACK_MAX];   // 256
U32 scope_depth;
```

**Arenas.**

```c
U8*  arena;                 // lexical, 1 MiB
U8*  ap, *amp;
U8*  const_arena;           // sized at init
U8*  cap;
U8** const_ptrs;
size_t const_arena_size;
```

**Output.**

```c
FILE* out;
FILE* in;
const char* const* argv;
int argc;
bool trace;
Sink sink;
Sink sink_stack[SINK_STACK_MAX];   // 64
int  sink_depth;
```

**Natives.**

```c
NativeFn natives[MAX_NATIVES];   // 32
```

## §4 — The dispatch loop

`vm_run` is a single `for(;;)` with a `switch(op)`. Shape of one
iteration:

```c
vm->current_pc = vm->pc;
OpCode op = (OpCode)READ();
if (vm->trace) { /* print */ }
switch (op) {
    case OP_PUSH: PUSH(READ()); break;
    ...
}
```

`READ()` reads `bytecode[pc]` and advances `pc`. Every operand is
read inline; the pc is already past the operands when the case
returns.

**`PUSH(val)`** stores at `data_stack[sp++]`.
**`POP()`** reads `data_stack[--sp]`.

Neither bounds-checks. The dispatch loop relies on codegen having
produced balanced bytecode; the validator does not check stack
depth (that would require a CFG analysis).

**`RT_ERR(fmt, ...)`** is the error macro for the dispatch loop
and for any helper that returns `int`. It formats the message,
sets `error_pc` and `error_func_idx` from the current call frame,
and `return 1` from the enclosing function.

**`NATIVE_ERR(vm, fmt, ...)`** is the error macro for natives.
Natives return `void`; the macro sets `native_failed = true` and
returns. The `OP_CCALL` case checks the flag after the native
call.

**Trace mode.** When `vm->trace` is set, each iteration prints
one line to stderr with the current pc, opcode number, and
stack depth. Enabled by `--trace`/`-t` on the driver.

## §5 — The opcode set

Thirty-nine opcodes, grouped by concern. Every case is
documented by its behavior in §6–§9 below; the enum itself is in
`vm.h`. Complete list in the order of the enum:

**Halt and stack:** `OP_HALT`, `OP_PUSH`, `OP_POP`, `OP_DUP`,
`OP_DUP2`.

**Locals:** `OP_LOAD_LOCAL`, `OP_STORE_LOCAL`,
`OP_LOAD_ADDR_LOCAL`.

**Indirect access:** `OP_LOAD_INDIRECT`, `OP_STORE_INDIRECT`,
`OP_LOAD_ADDR_INDIRECT`.

**Constants and length:** `OP_LOAD_CONST`, `OP_LEN`.

**Parameterized operators:** `OP_BINARY`, `OP_UNARY`.

**Control flow:** `OP_JMP`, `OP_JMP_IF_FALSE`, `OP_JMP_IF_TRUE`,
`OP_CALL`, `OP_CALL_INDIRECT`, `OP_CCALL`, `OP_RET`.

**Scope:** `OP_ENTER_SCOPE`, `OP_EXIT_SCOPE`.

**Allocation:** `OP_ALLOC`, `OP_ALLOC_RC`, `OP_NEW_ARRAY`,
`OP_NEW_RC_ARRAY`.

**Aggregate access and construction:** `OP_INDEX_LOAD`,
`OP_INDEX_STORE`, `OP_NEW_ENUM`, `OP_NEW_RC_ENUM`, `OP_TRAP`.

**Refcounting:** `OP_RC_INC`, `OP_RC_DEC`.

**Conversion:** `OP_CONVERT`.

**FFI:** `OP_FFI_CALL`.

**Error propagation:** `OP_TRY_JUMP_IF_OK`.

**Sub-op enums:** `OpBinary` (12 values: ADD, SUB, MUL, DIV, EQ,
NE, LT, LE, GT, GE, AND, OR), `OpUnary` (2 values: NEG, NOT),
`MemKind` (11 values: `MEM_I8` through `MEM_PTR`).

## §6 — Memory operations

### §6.1 The lexical arena

```c
static U8* arena_alloc(VM* vm, U64 size);
```

Rounds `ap` up to the next multiple of 8, checks the request
fits within `arena + ARENA_MAX` (1 MiB), advances `ap`, returns
the pointer. Returns NULL on exhaustion; every caller converts
NULL to `RT_ERR("arena out of memory …")`.

Alignment is 8 because every value the arena holds is either a
`U64` or a block whose first word is a `U64`.

### §6.2 The const arena

```c
static U8* const_alloc(VM* vm, U64 size);
```

Same shape as `arena_alloc` but bounded by
`const_arena + const_arena_size` (which is sized at init).

### §6.3 `materialize_consts`

Runs once from `vm_init` when a config is supplied. Two passes
over the pool:

1. Compute the total const-arena size (each `CONST_STRING` needs
   `RcHeader + 8 + bytes`; each `CONST_CSTRING` needs `bytes + 1`;
   every entry rounded up to 8). Aborts with `exit(1)` if the
   total exceeds `CONST_ARENA_MAX` (64 KiB).
2. Allocate the const arena and the `const_ptrs` array, then
   materialize each entry.

For a `CONST_STRING`, the block is
`[RcHeader][u64 length][bytes]`. The header's `ref_count` is set
to the sentinel `0xFFFFFFFF`, which makes `OP_RC_INC` and
`OP_RC_DEC` no-ops for const-arena strings. `const_ptrs[idx]`
points at the payload (after the header).

For a `CONST_CSTRING`, the block is `[bytes][NUL]` with no
header. `const_ptrs[idx]` points at the first byte.

`OP_LOAD_CONST` reads `const_ptrs[idx]` for both kinds.

### §6.4 The RC heap

`RcHeader` is 8 bytes: a 32-bit `ref_count` and 32 bits of
padding (to keep the payload 8-aligned). Every RC block is a
`malloc` of `sizeof(RcHeader) + payload_bytes`, with the payload
pointer being `(U8*)(h + 1)`.

`OP_ALLOC_RC`, `OP_NEW_RC_ARRAY`, and `OP_NEW_RC_ENUM` all
initialize `ref_count = 1` and push the payload pointer.

`OP_RC_INC` and `OP_RC_DEC` operate on the payload pointer.
Both check for NULL (no-op) and the const-arena sentinel
(no-op) before touching `ref_count`.

### §6.5 The deep drop

`OP_RC_DEC` takes a `TypeDesc` index operand. When the
refcount reaches zero, `rc_drop_deep(vm, value, desc)` runs:

- **`TD_STRING`** — decrement, free at zero.
- **`TD_RC`** — decrement; if zero, walk the payload based on
  the inner descriptor (a scalar slot, a nested `TD_RC`, or a
  compound payload), then free.
- **`TD_STRUCT` / `TD_ARRAY` / `TD_ENUM`** — call
  `rc_drop_payload`, which walks the fields, elements, or
  variant payloads and drops each in turn.
- **Everything else** (primitives, `TD_REF`, `TD_RAWPTR`) — no-op.

`rc_drop_payload` handles the three compound kinds:

- **`TD_STRUCT`** — for each `i` in `[0, count)`, read
  `payload + 8 + i*8` and `rc_drop_deep` with the field's
  descriptor (from `types->fields[aux + i]`).
- **`TD_ARRAY`** — read `[u64 length]`, then drop each element
  at `payload + 8 + i*8` with the element descriptor (from
  `types->aux`).
- **`TD_ENUM`** — read `[u64 tag]`; look up the variant in
  `types->enum_variants[aux + tag]`; drop each payload at
  `payload + 8 + i*8` with the payload descriptor from
  `types->enum_payloads[payload_start + i]`.

The walk is recursive: a `TD_RC` sub-value's own `rc_drop_deep`
runs if its count reaches zero. Deep structures cost O(sub-values)
per top-level drop.

## §7 — Locals and indirect access

### §7.1 `OP_LOAD_LOCAL`

```
LOAD_LOCAL slot
```

Reads `data_stack[fp + slot]` and pushes. Traps with
`"bad local load slot N"` if `fp + slot >= sp`.

### §7.2 `OP_STORE_LOCAL`

```
STORE_LOCAL slot
```

Pops the value, then writes it to `data_stack[fp + slot]`. If
the target slot is at or above the current `sp`, the VM grows
`sp` with zero-filled slots until `sp > target`, then writes.

The extension loop is why `let` codegen works with the
"locals-live-on-the-stack" convention. A `let x = e` leaves `e`
on the stack (which becomes the local's slot); a subsequent
anonymous slot (a pattern temporary) can be written with
`STORE_LOCAL` even though nothing was pushed for it. The frame
grows as needed.

Traps if `sp == 0` (nothing to pop) or `target >= DATA_STACK_MAX`.

### §7.3 `OP_LOAD_ADDR_LOCAL`

```
LOAD_ADDR_LOCAL slot
```

Pushes `&data_stack[fp + slot]` as a raw pointer. This is what
makes `&x` (where `x` is a local) cheap: no allocation.

The lifetime of the pointer is the enclosing frame; the escape
rules ensure it does not outlive the frame.

### §7.4 `OP_LOAD_INDIRECT` / `OP_STORE_INDIRECT`

```
LOAD_INDIRECT  offset  mem_kind
STORE_INDIRECT offset  mem_kind
```

`LOAD_INDIRECT` pops an address, reads from `address + offset`
with the width given by `mem_kind`, sign- or zero-extends as
appropriate, and pushes the `U64`. NULL is rejected with
`"null dereference"`.

`STORE_INDIRECT` pops the value, then the address, and writes
`value` at `address + offset` truncated to `mem_kind`'s width.
NULL is rejected.

`mem_kind` selects both width and (for sub-word loads) extension:

| `mem_kind` | Read/write | Load behavior |
|---|---|---|
| `MEM_I8` | 1 byte | sign-extend to I64 |
| `MEM_I16` | 2 bytes | sign-extend |
| `MEM_I32` | 4 bytes | sign-extend |
| `MEM_I64` / `MEM_U64` / `MEM_PTR` | 8 bytes | raw |
| `MEM_U8` | 1 byte | zero-extend |
| `MEM_U16` | 2 bytes | zero-extend |
| `MEM_U32` | 4 bytes | zero-extend |
| `MEM_F32` | 4 bytes | raw bit pattern |
| `MEM_F64` | 8 bytes | raw bit pattern |

### §7.5 `OP_LOAD_ADDR_INDIRECT`

```
LOAD_ADDR_INDIRECT offset
```

Pops an address, pushes `address + offset`. Used by:
- Sema's `&p.x` rewrite for extern struct fields.
- Codegen for `AST_ADDR_OF_FIELD`.
- Codegen for nested-by-value extern struct field access (the
  value's stack representation is its address).

## §8 — Aggregate operations

### §8.1 Arrays

Layout: `[u64 length][element0][element1]...`.

**`OP_NEW_ARRAY n`.** Arena-allocates `8 + n*8` bytes, writes
`n` at offset 0, then pops `n` values (in reverse LIFO order) and
writes them at `8 + (n-1-i)*8` for `i` in `[0, n)`. This yields
source order in the block. Pushes the block pointer.

**`OP_NEW_RC_ARRAY n`.** Same, but with an `RcHeader` prefix
and `ref_count = 1`.

**`OP_INDEX_LOAD desc`.** Pops the index, then the container
pointer. Reads the length from offset 0. Bounds-checks; traps
with `"index N out of bounds (length M)"` on failure. For
`TD_STRING`, reads the byte at `8 + index` and zero-extends to
`U64`. For `TD_ARRAY`, reads 8 bytes at `8 + index*8`. Other
descriptors trap with `"index load not supported for desc kind"`.

**`OP_INDEX_STORE desc`.** Pops the value, index, container.
Same bounds check. `TD_ARRAY` only; `TD_STRING` and everything
else trap.

### §8.2 Enums

Layout: `[u64 tag][payload0][payload1]...`.

**`OP_NEW_ENUM n`.** Arena-allocates `8 + n*8` bytes. Pops the
tag first (it was pushed last by codegen), writes it at offset 0,
then pops `n` payloads in reverse and writes them at
`8 + (n-1-i)*8`. Pushes the block pointer.

**`OP_NEW_RC_ENUM n`.** Same with an `RcHeader` prefix.

**`OP_TRAP idx`.** Reads the pool entry at `idx` (a
`CONST_STRING`) and reports its content as a runtime error.
Emitted by codegen as a defensive fall-through after a `match`'s
last arm.

## §9 — Control flow

### §9.1 Jumps

**`OP_JMP target`.** Unconditional. Sets `pc = target`.

**`OP_JMP_IF_FALSE target`.** Pops a `U64`. Jumps if the value
is 0 (integer zero is the only "false" the VM checks; it does
not distinguish bool from int).

**`OP_JMP_IF_TRUE target`.** Same, jumping on non-zero.

The targets are absolute word offsets into `bytecode[]`.

### §9.2 Calls and returns

**`OP_CALL func_idx argc`.** The full sequence is in
`runtime.md` §5.2. In summary: read `func_idx` and `argc`, bounds
check, push a `CallFrame` capturing the caller's `return_pc`,
`fp`, `amp`, and `scope_depth`, set `fp = sp - argc`, set
`amp = ap`, jump to `funcs[func_idx].entry_pc`.

**`OP_CALL_INDIRECT argc`.** The callee's codegen index is on the
stack, one below the args. The VM shifts the args down one slot
to overwrite the callee, then runs the same frame setup as
`OP_CALL`. This is why `AST_CALL_INDIRECT` pushes the callee
first and the args after.

**`OP_RET`.** Full sequence in `runtime.md` §5.3. In summary:
check `call_depth > 0` and `sp > fp`; pop the return value;
reset `ap = amp`; truncate `sp = fp`; push the return value;
restore `fp`, `amp`, `scope_depth`, `pc` from the popped frame.

### §9.3 Scopes

**`OP_ENTER_SCOPE`.** Pushes `{sp, amp}` onto `scope_stack`,
increments `scope_depth`, sets `amp = ap`.

**`OP_EXIT_SCOPE`.** Sets `ap = amp` (releasing the scope's arena
allocations), decrements `scope_depth`, then restores `sp` and
`amp` from `scope_stack[scope_depth]`.

The two-opcode pair is the only mechanism for arena reclamation.
Because the scope stack is separate from the data stack, a
scope's arena mark cannot be corrupted by a value push.

### §9.4 Error propagation

**`OP_TRY_JUMP_IF_OK target`.** Peeks the top-of-stack (which
must be an RC enum). Reads the tag at offset 0.

- **Tag == 0 (Ok / Some):** reads the payload at offset 8,
  inline-decrements the enum block's `ref_count` (free at zero,
  without deep drop — the payload is transferred to the caller
  and its refcount is untouched), replaces the top-of-stack with
  the payload, jumps to `target`.
- **Tag != 0 (Err / None):** leaves the block on the stack and
  falls through. Codegen emits `OP_RET` immediately after, which
  returns the block as the function's value.

NULL block is a runtime error.

## §10 — Parameterized operators

`OP_BINARY`, `OP_UNARY`, `OP_PRINT` (via `NATIVE_PRINT_VALUE`),
`OP_LEN`, `OP_INDEX_LOAD`, `OP_INDEX_STORE`, and `OP_CONVERT` all
take descriptor operands and dispatch on `TypeDesc.kind`.

### §10.1 `OP_BINARY sub desc`

Pops `b` then `a`. Dispatches on `desc->kind`:

- **Signed ints (`TD_I8`/`I16`/`I32`/`I64`).** Truncates the
  result to the descriptor's width after the operation. Signed
  arithmetic uses unsigned math internally (`(U64)a + (U64)b`)
  to make wrapping well-defined. Division by zero traps.
- **Unsigned ints (`TD_U8`/`U16`/`U32`/`U64`).** Same shape with
  unsigned truncation.
- **`TD_F32`.** Values are read/written through `U32` bit
  patterns (`memcpy` to/from `float`). NaN comparisons follow
  IEEE 754. Division by zero (`b == 0.0f`) traps.
- **`TD_F64`.** Same with 8-byte values.
- **`TD_STRING`.** `OPB_ADD` allocates a fresh RC string and
  concatenates. Comparisons are lexicographic via
  `strings_compare`. Other operators trap.
- **`TD_RAWPTR`.** `OPB_EQ` and `OPB_NE` only; other operators
  trap.

Comparison operations push `0` or `1` as `U64`. Arithmetic ops
push the result.

### §10.2 `OP_UNARY sub desc`

- **`TD_I8`/`I16`/`I32`/`I64`.** `OPU_NEG` with width truncation.
- **`TD_F32`/`TD_F64`.** `OPU_NEG`.
- **`TD_BOOL`.** `OPU_NOT`.

Other descriptor kinds trap with `"unary not supported"`.

### §10.3 `OP_CONVERT from to`

Reads the raw stack word, interprets it as `from`, converts to
`to`, pushes.

The `SRC_IS_*` macros classify the source kind. Conversion
matrix:

- **To signed int:** int sources cast through `I64`; float
  sources trap on NaN and out-of-`I64`-range values; the result
  is truncated to the target's width and sign-extended.
- **To unsigned int:** int sources pass through; float sources
  trap on NaN and negative; truncation to the target's width,
  zero-extension.
- **To `f64`:** signed int / bool via `(double)(I64)`, unsigned
  via `(double)U64`, float via widening.
- **To `f32`:** same with `float`.
- **To `bool`:** int sources check `!= 0`; floats check
  `!= 0.0 && !isnan`.

Other target kinds trap.

### §10.4 `OP_LEN desc`

Pops a container pointer. If NULL, pushes 0. Otherwise reads
the `u64 length` at offset 0. `desc` must be `TD_STRING` or
`TD_ARRAY`; others trap.

### §10.5 `NATIVE_PRINT_VALUE`

Not an opcode. A native invoked via `OP_CCALL
NATIVE_PRINT_VALUE`. The stack layout is `[value][desc_idx]`;
the native pops both and calls `vm_print_value(vm, desc, value)`.

## §11 — Value rendering

`vm_print_value(vm, d, raw)` recurses through compound types.

**Scalars.** Signed ints `%lld`, unsigned `%llu`, floats `%g`,
bools `"true"`/`"false"`.

**Strings.** The payload pointer (after the `RcHeader`) is
`[u64 length][bytes]`; the native writes `length` bytes at
`payload + 8`.

**References and RC handles.** Printed as `%llu` (the pointer
value). Not hex; readable, not a debugger.

**`TD_RAWPTR`.** If the pointee descriptor is `TD_STRUCT` or
`TD_EXTERN_STRUCT`, the pointed-to struct's contents are printed
rather than the address. Otherwise the raw value.

**`TD_ARRAY`.** `[e0, e1, ...]`. Each element printed with the
element descriptor from `d->aux`.

**`TD_STRUCT`.** `{f0, f1, ...}`. Field descriptors from
`types->fields[d->aux + i]`.

**`TD_EXTERN_STRUCT`.** `{f0, f1, ...}` with C-ABI offsets.
Reads each field's bytes with `desc_align` to determine the
offset, using the field's natural width. Nested extern structs
recurse.

**`TD_ENUM`.** The variant name (from `types->enum_variants`)
followed by `(payloads)` if the variant has any. Out-of-range
tags render as `<enum #N>`. Payload descriptors from
`types->enum_payloads`.

Rendering goes to the current sink (see §12), not directly to
stdout.

## §12 — Sinks and print

### §12.1 The sink

```c
typedef struct {
    SinkKind kind;
    FILE*    file;
    uint8_t  inline_buf[SINK_INLINE_CAP];   // 128
    uint8_t* buf;
    size_t   len;
    size_t   cap;
} Sink;
```

A destination for written bytes. Three kinds: `SINK_STDOUT`,
`SINK_STDERR`, `SINK_STRING`.

- For stdout/stderr sinks, `file` is the target `FILE*`.
- For string sinks, bytes accumulate into `buf`. `buf` starts
  pointing at `inline_buf`; `sink_grow` allocates a heap buffer
  when needed.

### §12.2 `native_str_begin` / `native_str_end`

`NATIVE_STR_BEGIN` saves the current sink on `sink_stack` and
installs a fresh `SINK_STRING` sink.

`NATIVE_STR_END` materializes the accumulated bytes into a fresh
RC string (`[RcHeader][u64 len][bytes]`), frees the heap buffer
if the sink grew, restores the previous sink, and pushes the
string pointer.

Nested `BEGIN`/`END` pairs are legal; each pair is one level on
`sink_stack`. `SINK_STACK_MAX = 64`.

### §12.3 `NATIVE_PRINT_VALUE`

Appends a value's rendering to the current sink. See §10.5 and
§11.

### §12.4 `NATIVE_STDOUT_WRITE` / `NATIVE_STDERR_WRITE`

Pop a string payload pointer. If NULL, return silently.
Otherwise write `[u64 len][bytes]` to the target `FILE*` and
flush.

`STDOUT_WRITE` uses `vm->out` if set, otherwise `stdout`.
`STDERR_WRITE` ignores `vm->out`.

## §13 — Natives

`vm_init` registers 21 natives. Each is a `void (*)(VM*)` that
pops its arguments and pushes its result.

**Output:** `NATIVE_STDOUT_WRITE`, `NATIVE_STDERR_WRITE`,
`NATIVE_PRINT_VALUE`, `NATIVE_STR_BEGIN`, `NATIVE_STR_END`.

**FFI marshalling:** `NATIVE_FFI_CSTRING`, `NATIVE_FFI_STRING`,
`NATIVE_FFI_ERROR`, `NATIVE_FFI_ERRNO`, `NATIVE_FFI_ALLOC`,
`NATIVE_FFI_FREE`.

**Raw pointer primitives:** `NATIVE_RAW_NULL`,
`NATIVE_RAW_IS_NULL`, `NATIVE_RAW_OFFSET`,
`NATIVE_RAW_LOAD_U8`, `NATIVE_RAW_STORE_U8`.

**Arena helpers:** `NATIVE_ARENA_ZERO`, `NATIVE_MEMCPY`.

**Program I/O:** `NATIVE_ARGS`, `NATIVE_READ_LINE`,
`NATIVE_READ_ALL`.

Details for each are in the source. The ones worth noting:

**`NATIVE_ARGS`.** Builds `rc<[string]>` from `vm->argv`. Each
element is a fresh RC string copy of the argument. The array is
a fresh RC block with refcount 1. Arguments are capped at 64.

**`NATIVE_READ_LINE`.** Reads one line from `vm->in` (or stdin)
into a fresh RC string. Strips a trailing `\r\n`. Wraps the
result in `Option.Some` (tag 0) with the string as payload; EOF
with no bytes read returns `Option.None` (tag 1) with no
payload.

**`NATIVE_READ_ALL`.** Reads all of stdin into a fresh RC
string.

**`NATIVE_ARENA_ZERO`.** Pops a size, arena-allocates that many
zeroed bytes, pushes the pointer. Used by extern struct literals
to allocate C-layout memory.

**`NATIVE_MEMCPY`.** Pops `n`, `src`, `dst`, calls `memcpy`
(guarded against any being zero), pushes 0 (the void result).

**`NATIVE_FFI_STRING`.** Walks the C string to find its length
(there is no length to check; a non-NUL-terminated string would
read off the end), allocates a fresh RC string, copies the
bytes.

**`NATIVE_FFI_CSTRING`.** Pops a Prism string, arena-allocates
`length + 1` bytes, copies the bytes, NUL-terminates, pushes the
pointer. The result lives until the enclosing scope exits.

**`NATIVE_FFI_ERROR` / `NATIVE_FFI_ERRNO`.** Read the VM's
`ffi_error` / `ffi_errno` and push.

**`NATIVE_FFI_ALLOC` / `NATIVE_FFI_FREE`.** `calloc(1, size)` and
`free`. Not RC-tracked; the user frees via `ffi_free`.

## §14 — The FFI path

The two functions in this section run when `OP_FFI_CALL` is
executed.

### §14.1 `ffi_resolve`

Called on the first invocation of a given `FFIFunc`. It:

1. Loads the library if not already loaded.
   - Windows: `LoadLibraryA(lib->path)`.
   - Unix: `dlopen(lib->path, RTLD_LAZY | RTLD_GLOBAL)`.
2. Resolves the symbol.
   - Windows: `GetProcAddress(handle, symbol)`, falling back to
     `_<symbol>` for 32-bit cdecl decoration.
   - Unix: `dlerror(); dlsym(handle, symbol)`.
3. Prepares the libffi cif. Fills `ffi_arg_types[]` with the
   `ffi_type*` for each `FFIType` (via `ffi_type_of_kind`), then
   calls `ffi_prep_cif` for non-variadic or `ffi_prep_cif_var`
   for variadic.
4. Sets `cif_ready = true`, `last_varargc = arg_count`.

Failure at any step writes `vm->error` and returns 1.

**Windows symbol decoration.** 32-bit Windows decorates cdecl
symbols with a leading underscore. The fallback `GetProcAddress`
with `_<symbol>` covers the case where the plain name is not
found.

**`ffi_arg_types[]` persistence.** The array lives on `FFIFunc`,
not the stack, because `ffi_prep_cif` stores a pointer to it, not
a copy. `MAX_FIXED_ARGS = 8`, `MAX_TOTAL_ARGS = 16`.

### §14.2 `ffi_call_dispatch`

Called from `OP_FFI_CALL` with `fidx` and `argc`.

1. Bounds-check `fidx` and `argc` before taking a pointer into
   `vm->ffi->funcs[]`.
2. If `!cif_ready`, call `ffi_resolve`.
3. For a variadic function whose `argc` differs from the last
   prepared cif, rebuild the cif. The fixed args keep their
   declared types; the varargs are all typed `sint64` (which
   works for all the allowed variadic types: integers, bool, and
   pointers).
4. Pop `argc` args. The stack's top is the last argument, so the
   values are stored in reverse (`slots[argc-1-i] = POP()`).
   For an `Option<*T>` param, unwrap the enum: tag 0 reads the
   payload pointer, tag 1 becomes NULL.
5. `argv[dst] = &slots[dst]` — libffi wants an array of pointers
   to the argument values.
6. `errno = 0; ffi_call(&f->cif, fn_ptr, &result, argv);
   vm->ffi_errno = errno;`
7. Push the result:
   - **`returns_option_ptr`** — wrap in `Option.Some(ptr)` (tag
     0, payload) or `Option.None` (tag 1, no payload).
   - **`FFI_VOID`** — push 0.
   - **Integer/pointer/float** — narrow to the declared width
     (sign- or zero-extend as appropriate) and push.
   - **`FFI_BOOL`** — push `0` or `1`.

Failure at any step traps with a runtime error.

### §14.3 The `Option<*T>` convention

Sema identifies `Option<*T>` via `is_option_ptr_type` and sets two
flags on the `FFIFunc`: `returns_option_ptr` and
`arg_is_option_ptr[]`. The VM uses those flags to unwrap and
wrap. See `language/reference.md` §13.5 for the user-facing
convention.

## §15 — Invariants

- **I44** — `sp <= DATA_STACK_MAX` before every push. Checked on
  most pushes; some paths rely on codegen having produced balanced
  bytecode.
- **I45** — `fp + slot < sp` before every `LOAD_LOCAL`. Checked.
  `STORE_LOCAL` extends the stack if needed.
- **I46** — `ap <= arena + ARENA_MAX` before every allocation.
  Checked in `arena_alloc`.
- **I47** — `amp` is always a valid prior `ap`. Enforced by
  construction (only `OP_ENTER_SCOPE`, `OP_CALL`, `OP_RET` set
  `amp`, each to a value previously read from `ap` or saved on
  the stack).
- **I48** — every call frame's `return_pc` is the address just
  after the `CALL` instruction.
- **I49** — every `OP_RET` corresponds to a prior `OP_CALL`, and
  `call_depth` never goes negative.
- **I50** — every `LOAD_CONST idx` has a valid materialized
  pointer for `idx`. Enforced by `materialize_consts` at init.
- **I51** — `const_arena_size` is at least the total computed by
  `materialize_consts`. Enforced by an `exit(1)` if the total
  exceeds `CONST_ARENA_MAX`.
- **I52** — `RcHeader.ref_count == 0xFFFFFFFF` implies the block
  is in the const arena. Set by `materialize_consts` for all
  const-arena string headers; checked by `OP_RC_INC`/`OP_RC_DEC`.
- **I53** — every RC block's header is at `payload - 8`.

## §16 — Known limitations

**Fixed caps.** `DATA_STACK_MAX = 4096`, `CALL_STACK_MAX = 256`,
`SCOPE_STACK_MAX = 256`, `ARENA_MAX = 1 MiB`,
`CONST_ARENA_MAX = 64 KiB`, `MAX_NATIVES = 32` (21 registered),
`MAX_FIXED_ARGS = 8`, `MAX_TOTAL_ARGS = 16`, `SINK_STACK_MAX =
64`, `SINK_INLINE_CAP = 128`.

**No stack-depth check before every push.** A codegen bug that
overflows the data stack traps at the first `LOAD_LOCAL` or
similar that reads past `sp`; a program that only pushes without
loading would read past the array. Not observed in practice.

**No bytecode validation.** `vm_run` trusts the chunk's structure.
`validate_bytecode` runs before, but only checks opcode ranges and
operand bounds; it does not check stack balance or descriptor
consistency.

**No memory protection for the RC heap.** A double-free or a
use-after-free produces undefined behavior, not a clean runtime
error.

**No signal handling.** A crashing C function (called via the
FFI) crashes the VM.

**The RC heap does not free at VM shutdown.** A program that
leaks RC blocks leaks them for the process's lifetime. There is
no final GC. `vm_free` releases the arena, the const arena, and
the sink buffers, but not the RC heap.

**`ffi_error` is overwritten on every failure.** The FFI
machinery does not keep a history; the last dlerror message
wins.

**`Option<*T>` marshalling assumes the enum has two variants.**
The unwrap reads tag 0/1; a user-defined enum with a different
shape would be miscategorized. The recognizer in
`sema_ffi.c` prevents this from being reachable.

**The FFI variadic ABI assumes C default promotions.** Floats
are rejected at sema; everything else is passed as `sint64`
(which works for the allowed types). Not tested against a
non-x86_64 ABI.

**No thread safety.** Every state mutation is a plain read or
write. A multi-threaded program would race. The compiler and VM
are single-threaded.

**The trace print goes to stderr unconditionally.** Not
configurable per-run without a rebuild.

## §17 — Extension points

- **Adding an opcode.** `vm.h` (enum), `vm.c` (case in `vm_run`),
  `disasm.c` (`OPINFO` row, validator case, operand rendering).
  See `arch/recipes.md` §Adding an opcode.
- **Adding a native.** `vm.h` (`NativeId`), `vm.c` (implementation
  and `vm_register_native` call), `disasm.c` (name table for
  `OP_CCALL` rendering), `codegen.c` (emission via `OP_CCALL`).
- **Adding a numeric type.** A new `TypeDescKind`, a new case in
  `desc_kind_of`, a new case in each parameterized opcode's
  dispatch. No new opcodes.
- **Optimization.** A peephole pass over `bytecode` before
  `validate_bytecode`.
- **A stack-balance validator.** Extends `validate_bytecode` with
  a CFG walk that tracks depth per instruction.
- **A debugger interface.** No breakpoints, no stepping, no
  inspection; `vm_run` is a closed loop.
- **Signal handlers for FFI crashes.** Would need per-platform
  `sigaction`/`SetUnhandledExceptionFilter` and a way to report
  from a signal context.
- **RC heap instrumentation.** No counters for live blocks,
  total allocations, or peak.
- **JIT.** No path.
